# index‑management.md
## 1 环境基线
- Kubernetes v1.32、containerd
- 采集组件：Fluent‑Bit
- 缓冲层：Kafka
- 存储引擎：Loki / Elasticsearch / ClickHouse
- 核心目标：分别管控标签索引、倒排索引、MergeTree分区索引，规避索引膨胀、标签爆炸、分片过多、分区泛滥等典型线上故障

## 2 索引总览对比
|存储组件|索引类型|索引存储对象|管控重点|
|---|---|---|---|
|Loki|标签索引（Label‑Index）|仅索引标签，日志正文无索引|严格控制标签基数，禁止动态字段作为标签|
|Elasticsearch|倒排索引|全日志字段分词索引|分片数量、ILM生命周期、段合并优化|
|ClickHouse|MergeTree主键稀疏索引|分区+主键索引|按日分区、控制分区总量、合理设计主键顺序|

## 3 Loki 标签索引管理
### 3.1 索引原理
Loki 只对标签建立倒排索引；日志正文以压缩Chunk存放，查询阶段解压后正则匹配。
标签索引记录「标签‑标签值 → Chunk编号映射关系」。

### 3.2 允许使用的标准标签（白名单）
```
namespace_name
pod_name
deployment_name
container_name
node_name
env
```
只保留枚举型、固定值字段；traceId、request‑id、用户编号、随机值**禁止设置标签**，放入日志正文。

### 3.3 标签基数硬性阈值
1. 全局标签组合总数 ≤ 100000
2. 单标签唯一值上限：pod_name ≤ 5000；namespace ≤ 20

### 3.4 日常管控手段
1. Distributor开启标签校验，拦截超高基数标签
2. Prometheus监控指标 `loki_labels_cardinality`
3. 新业务上线前审核标签配置
4. 动态字段通过Fluent‑Bit modify插件移除k8s标签集合

### 3.5 索引故障处理
- 标签爆炸：立刻关闭异常标签，清理旧Chunk，重建索引
- 查询缓慢：标签过少，补充业务常用筛选标签

## 4 Elasticsearch 索引与分片管理
### 4.1 索引命名规范
采用按天滚动索引：`container‑log‑20260805`
- 业务日志、系统日志、审计日志分为三类独立索引前缀

### 4.2 分片规划标准
1. 单分片磁盘体积维持 30‑50GB
2. 单天索引分片数：3～8
3. 生产环境副本数 = 1；审计日志副本数 = 2
4. 分片总数不宜超过节点数 ×8，防止集群元数据压力过高

### 4.3 ILM 索引生命周期管理
1. 热阶段 0‑3d：读写、高性能SSD磁盘
2. 温阶段 3‑7d：关闭写入，减少副本
3. 冷阶段 7‑15d：迁移低速存储，关闭索引
4. 超过TTL：自动删除索引

### 4.4 段合并管控
1. 段合并IO压力大，配置业务低峰期执行合并任务
2. 单分片段数量控制在20以内
3. 高峰期临时禁用强制合并，避免抢占磁盘IO

### 4.5 索引禁用规范
不需要分词查询的字段设置为 `index: false`，减少索引体积。

## 5 ClickHouse MergeTree 分区与主键索引管理
### 5.1 分区管理
1. 分区键统一采用日期 `toYYYYMMDD(log_time)`，按天分区
2. 单分区磁盘大小维持10‑30GB
3. 集群全部分区总数上限建议小于10000；分区过大会拖慢启动、元数据加载、查询性能

### 5.2 主键索引设计
主键遵循：**时间字段前置，高频筛选字段后置**
```sql
ORDER BY (log_time, namespace, pod_name)
```
稀疏索引只标记数据块起始值，依靠分区裁剪 + 主键索引跳过大量数据块。

### 5.3 二级索引（Skip‑Index）
高频过滤字段可添加跳跃索引，加快日志关键字过滤。

### 5.4 分区运维命令
```sql
-- 查看分区列表
SELECT partition,name FROM system.parts WHERE table = 'container_log'
-- 删除过期分区
ALTER TABLE container_log DROP PARTITION '20260801'
```

## 6 Kafka 索引说明
Kafka存在日志偏移索引、时间索引，由broker自动维护，人工无需干预；
仅需要管控分区数量，不属于业务检索索引。

## 7 全平台索引通用最佳实践
1. 索引只存放用于筛选的枚举字段，动态唯一值全部存入日志正文
2. 时间字段作为第一级索引/分区条件，所有查询优先依靠时间裁剪数据范围
3. 监控指标：标签基数、分片数量、分区数量、段合并耗时、索引磁盘占用
4. 审计日志使用独立数据表、独立索引链路，不和业务日志共用索引资源
5. 索引配置纳入Git版本管理，ArgoCD统一下发

## 8 高频索引类故障清单
1. Loki标签基数爆炸 → 索引内存溢出、查询超时
2. ES分片数量过多 → 集群元数据压力高、节点GC频繁
3. ES段合并争抢IO → 写入延迟升高
4. ClickHouse分区数量上万 → 数据表加载缓慢、查询性能下滑
5. 主键顺序不合理，无法触发分区裁剪与稀疏索引过滤
