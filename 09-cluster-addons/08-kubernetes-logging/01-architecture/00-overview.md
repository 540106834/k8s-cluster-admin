# overview.md
## 1.文档目标
本文档用于定义集群日志平台的建设目标、业务覆盖范围、功能边界、环境基线、非功能指标，作为整套日志体系顶层设计文档，约束后续架构、组件、运维、安全方案的设计方向。

## 2.建设背景
Kubernetes v1.32集群业务日志分散在节点容器运行时文件、标准输出、业务内部日志文件、系统内核日志、k8s‑apiserver审计日志。  
缺少统一采集、清洗、检索、脱敏、过期清理、告警能力；故障排查依赖登录节点查看容器日志，多微服务链路排查低效，敏感日志存在泄露风险，需要搭建一套生产级可观测日志底座。

## 3.平台建设目标
### 3.1 业务目标
1. 统一接管集群内全部容器 stdout/stderr 标准输出日志
2. 支持节点系统日志、kubelet日志、集群审计日志、业务文件日志接入
3. 实现日志结构化解析、字段提取、标签标记、敏感数据脱敏
4. 支持开发人员按照命名空间、Pod、工作负载、标签快速检索日志
5. 日志生命周期自动管理：分片、过期删除、冷热分层、备份归档

### 3.2 稳定性目标
1. 采集Agent单节点部署，Agent故障不影响节点上业务容器运行
2. 网络抖动、存储后端不可用时采集端具备本地缓冲，尽可能防止日志丢失
3. 日志平台自身指标接入Prometheus，采集丢弃量、写入延迟、磁盘占用配置告警
4. 支持水平扩容，应对业务流量上涨带来的日志吞吐量激增

### 3.3 安全目标
1. Agent‑存储后端之间传输开启TLS加密
2. RBAC权限隔离，不同项目人员仅可访问自身命名空间日志
3. 自动识别并脱敏密钥、账号、令牌、手机号等敏感字段
4. 独立留存集群审计日志，用于集群操作溯源

## 4.功能边界
### 4.5 采集范围（纳入管理）
- 容器标准输出、标准错误日志（containerd运行时日志文件）
- /var/log 节点系统日志、kubelet日志
- kubernetes apiserver audit 审计日志
- 业务容器挂载目录输出的本地文件日志

### 4.2 不在平台能力范围内
- 业务数据库慢查询日志、中间件独立日志（由中间件自身exporter采集）
- 日志长期离线归档至对象存储以外的复杂大数据分析
- 业务日志‑链路追踪‑监控指标深度关联（交由可观测整体平台负责）

## 5.环境基线
- Kubernetes 版本：v1.32
- 容器运行时：containerd
- 配置管理：Git 托管全部采集规则、过滤规则；GitOps 下发配置
- Helm Chart 源：离线MinIO仓库
- 持久化存储：nfs‑sc 作为日志组件PVC存储类
- 采集Agent选型：Vector为主，Fluent‑Bit作为备选方案
- 存储引擎：Loki作为主存储，Elasticsearch用于全文检索场景
- 可视化面板：Grafana

## 6.非功能指标
1. 日志推送延迟：正常环境下延迟＜3s
2. Agent崩溃重启后缓冲区日志不会丢失
3. 单节点Agent日志吞吐上限 ≥100MB/s
4. 普通关键字日志查询响应时长＜2s
5. 日志磁盘存储自动回收，严格遵守留存周期
6. Agent设置CPU、内存资源上限，禁止抢占业务节点资源

## 7.平台受众
- SRE运维人员：平台部署、调优、故障排查、容量规划
- 开发工程师：业务运行日志查询、异常堆栈排查
- 安全负责人：审计日志查看、敏感日志巡检、数据脱敏管控
