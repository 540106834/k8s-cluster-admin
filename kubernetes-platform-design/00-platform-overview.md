# kubernetes-platform-design/00-platform-overview.md
## 文档元信息
- 模块：平台总体架构
- 优先级：★★★★★ 核心顶层设计文档
- 定位：全平台所有子模块的总纲领、分层边界、统一约束标准，所有下层文档均以此文档为基准对齐
- 适用人群：平台架构师、SRE负责人、集群运维、安全合规负责人、平台产品负责人

## 1. 平台建设目标
### 1.1 核心业务目标
1. **多租户隔离交付**：支撑研发、测试、预发、生产多环境，按业务线/团队强隔离，资源、网络、权限互不干扰
2. **标准化应用托管**：统一容器应用部署、发布、伸缩、配置、存储标准，消除业务自定义差异化运维
3. **全链路安全闭环**：从镜像供应链、集群访问、网络、容器运行、密钥、审计构建完整安全防线
4. **可观测自治运维**：指标/日志/链路/告警一体化，故障自动识别、自动告警、自愈能力
5. **可扩展集群生命周期**：支持单集群、多集群、跨区域集群统一管控，平滑升级、扩容、容灾切换
6. **平台工程化自助服务**：基于GitOps实现研发自助交付，降低K8s使用门槛，减少运维人工介入

### 1.2 非功能指标（SLA约束）
1. 集群控制平面可用性 ≥99.99%
2. 业务应用发布中断时长 ≤30s
3. 核心数据定时备份，RPO≤15min，RTO≤1h
4. 审计日志留存 ≥180天，满足合规要求
5. 平台组件版本每年至少1次大版本升级，漏洞修复周期≤7天

## 2. 平台分层架构（五层标准分层模型）
自上而下定义边界，每层职责清晰，依赖单向向下，禁止跨层逆向耦合
```
┌─────────────────────────────────────┐
│ 五层：平台工程自助层（IDP）          │ GitOps、开发者门户、自助流水线、交付模板
├─────────────────────────────────────┤
│ 四层：应用业务运行层                │ Workload、Ingress、HPA、配置、密钥、发布策略
├─────────────────────────────────────┤
│ 三层：集群资源管控层                │ 计算/存储/网络/权限/命名空间/镜像供应链/可观测
├─────────────────────────────────────┤
│ 二层：K8s基础底座层                 │ K8s原生API、集群生命周期、系统插件、准入控制器
├─────────────────────────────────────┤
│ 一层：基础设施资源层                │ 服务器、虚拟化、存储硬件、负载均衡、网络设备
└─────────────────────────────────────┘
```
### 分层详细职责
#### 第一层：基础设施资源层
- 物理/虚拟机节点、CPU内存磁盘网络硬件资源池
- 底层负载均衡、防火墙、存储阵列、底层网络交换机
- 节点操作系统基线、内核参数标准化
- 关联文档：09-compute-resource-management.md、12-cluster-lifecycle-management.md

#### 第二层：K8s基础底座层
- Kubernetes控制平面（etcd、kube-apiserver、controller-manager、scheduler）
- 集群生命周期：部署、升级、扩缩容、版本治理
- 系统基础插件集：CoreDNS、metrics-server、cert-manager、CSI驱动、Ingress Controller
- 全局准入控制器、集群审计、集群级安全策略
- 关联文档：11-addon-management.md、12-cluster-lifecycle-management.md、15-compliance-audit.md

#### 第三层：集群资源管控层（平台核心管控域）
平台核心能力中枢，拆分7大能力域，覆盖目录中01~10、13所有模块
1. **访问权限域**：认证、授权、RBAC、kubeconfig、OIDC单点登录（01-cluster-access-management.md）
2. **租户资源域**：Namespace隔离、资源配额、LimitRange、多租户管控（02-namespace-resource-governance.md）
3. **镜像供应链域**：镜像仓库、构建流水线、镜像扫描、拉取权限管控（03-image-supply-chain.md）
4. **网络安全域**：CNI、NetworkPolicy、流量管控、服务网络隔离（05-network-security.md）
5. **存储持久化域**：CSI、StorageClass、PV/PVC、快照、数据备份（06-storage-platform.md）
6. **可观测域**：指标、日志、追踪、告警、大盘、故障诊断（07-observability-platform.md）
7. **安全管控域**：密钥管理、容器运行安全、节点调度、容灾恢复（08/09/10/13）

#### 第四层：应用业务运行层
面向研发的应用标准化运行规范，统一所有业务应用交付模型
- 标准工作负载：Deployment/StatefulSet/DaemonSet/CronJob
- 流量暴露：Service、Ingress、灰度/蓝绿发布策略
- 配置与敏感数据：ConfigMap、Secret、外部密钥系统对接
- 弹性伸缩：HPA、VPA、集群自动扩缩节点
- 关联文档：04-application-delivery.md

#### 第五层：平台工程自助层（IDP）
将底层K8s能力封装为标准化自助产品，屏蔽底层复杂度
- GitOps统一交付流水线（ArgoCD）
- 应用模板库、环境自助申请、资源自助扩容
- 开发者门户、API网关、自助审计查询
- 关联文档：14-platform-engineering.md

## 3. 平台核心能力模型
### 3.1 租户隔离能力模型
- 软隔离：Namespace + ResourceQuota + LimitRange + RBAC权限边界
- 网络隔离：NetworkPolicy阻断跨命名空间非法Pod通信
- 硬隔离：节点污点/亲和性实现业务专属节点池、多集群物理隔离
- 数据隔离：独立StorageClass、独立镜像仓库项目、独立密钥存储

### 3.2 安全能力模型（全生命周期安全）
1. 供应链安全：代码扫描 → 镜像构建扫描 → 仓库漏洞拦截
2. 集群访问安全：OIDC认证、细粒度RBAC、证书轮换、操作审计
3. 网络安全：默认拒绝NetworkPolicy、Ingress HTTPS、流量加密
4. 容器运行安全：PSA基线、SecurityContext、准入控制器拦截高权限容器
5. 密钥安全：外部密钥管理系统，禁止明文Secret，自动轮换密钥
6. 合规审计：全量API操作日志留存、策略巡检、周期性安全评估

### 3.3 资源调度与供给模型
1. 计算资源：多节点池分组，标签/污点区分生产/测试/中间件节点
2. 存储资源：块存储/文件存储/对象存储多StorageClass，快照与备份策略
3. 网络资源：集群内部Service网络、南北向Ingress、多网段隔离
4. 弹性供给：应用HPA自动扩缩Pod、集群节点自动伸缩

### 3.4 可观测自治模型
- 三层观测：基础设施指标 → 集群资源指标 → 业务应用指标
- 日志全收集：容器标准输出、容器日志、节点系统日志、审计日志
- 分布式追踪：微服务调用链路采集
- 告警分级：P0故障自动电话告警、P1短信、P2站内消息，配套自愈脚本

### 3.5 容灾与生命周期模型
1. 集群生命周期：一键部署、版本滚动升级、节点无损替换
2. 数据容灾：etcd定时备份、PV定时快照、跨集群数据备份
3. 故障容灾：控制平面多副本、多集群异地灾备、故障切换流程

## 4. 平台统一设计原则（所有模块强制遵守）
### 4.1 标准化原则
1. 所有资源必须使用统一Label/Annotation规范，用于分租户、分环境、分业务标识
2. 禁止业务自定义CRD、自定义控制器，统一使用平台提供标准能力
3. 所有YAML资源统一通过Git管理，禁止直接kubectl apply裸操作集群

### 4.2 最小权限原则
1. RBAC权限按业务最小范围授予，禁止cluster-admin普通研发账号
2. 容器运行默认禁止root用户，禁止特权容器、挂载宿主机敏感目录
3. 镜像拉取、密钥访问、存储挂载均做细粒度权限管控

### 4.3 左移安全原则
安全检查前置至开发、构建阶段，而非仅在运行时拦截：代码扫描→镜像扫描→准入校验→运行时监控

### 4.4 可观测全覆盖原则
所有平台组件、业务应用必须开启指标、日志采集，无例外白名单

### 4.5 故障自治原则
核心组件支持副本高可用，配置自愈策略，减少人工介入处理常规故障

### 4.6 可扩展兼容原则
平台设计兼容多K8s版本、多CNI、多CSI、多密钥系统，无厂商锁定，支持平滑替换组件

### 4.7 合规可审计原则
所有集群操作、资源变更、密钥访问、镜像拉取均留存日志，支持溯源审计

## 5. 模块依赖与协作关系
### 5.1 核心依赖流向
1. 底座层（二层）是所有上层模块基础，集群异常会导致所有上层能力失效
2. 集群资源管控层（三层）为应用层、平台工程层提供底层能力支撑
3. 平台工程层（五层）仅封装下层能力，不直接修改集群底层资源逻辑

### 5.2 模块协作边界示例
1. 01访问管理 + 02命名空间治理：联合实现多租户权限隔离
2. 03镜像供应链 + 10工作负载安全：镜像漏洞拦截+容器运行安全双重防护
3. 05网络安全 + 04应用交付：Ingress流量管控 + Pod网络隔离
4. 07可观测平台：对接所有模块采集指标日志，统一告警输出
5. 14平台工程：整合01~13所有底层能力，封装自助交付流程

## 6. 平台约束与禁忌规范
1. 禁止跨Namespace无限制通信，未配置NetworkPolicy视为安全缺陷
2. 禁止业务直接操作底层节点、修改kubelet/内核参数，统一由平台管控
3. 禁止明文存储账号密码，所有敏感信息必须接入密钥管理系统
4. 禁止无配额无资源限制的Namespace，所有租户必须配置ResourceQuota
5. 禁止集群组件单副本运行，控制平面、核心插件必须多副本高可用
6. 禁止跳过GitOps直接在集群临时创建资源，临时测试资源需标注生命周期标签

## 7. 文档使用规范
1. 本文件为顶层基准，其余14份模块文档所有设计必须对齐本文分层、原则、能力模型
2. 新增平台能力模块，必须先更新本文档分层与能力模型，再新建对应md文件
3. 平台架构评审、方案设计、故障复盘均以本文档架构分层作为沟通统一语言
4. 每年一次架构复盘，更新本文档目标、SLA、设计原则适配业务规模变化
