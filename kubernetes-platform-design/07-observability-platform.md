# kubernetes-platform-design/07-observability-platform.md
## 文档元信息
- 模块：可观测平台
- 优先级：★★★★★ 集群故障诊断、业务稳定性核心底座
- 依赖文档：00-platform-overview.md、02-namespace-resource-governance、04-application-delivery
- 关联模块：05-network-security、06-storage-platform、09-compute-resource-management、14-platform-engineering、15-compliance-audit
- 适用角色：SRE、监控运维、研发效能、安全工程师、故障复盘负责人

## 1. 模块定位与核心目标
### 1.1 定位
归属三层「集群资源管控域-可观测域」，构建**指标(Metrics)、日志(Logging)、链路(Tracing)、告警(Alert)四大支柱**一体化观测底座，覆盖基础设施、集群、平台组件、业务应用全层级数据采集、存储、检索、可视化、告警闭环。
平台所有模块、业务负载强制接入观测体系，是故障定位、容量规划、性能优化、安全审计、SLA统计唯一数据源。

### 1.2 核心目标
1. 统一采集标准，消除业务自建监控、日志组件碎片化问题
2. 分层数据采集：宿主机→K8s集群→平台插件→业务微服务全覆盖
3. 数据分级存储冷热分离，平衡查询性能与存储成本
4. 标准化告警分级、自愈流程，区分故障优先级，减少告警噪音
5. 基于租户标签做数据权限隔离，研发仅可查看自身团队观测数据
6. 统一故障诊断链路：指标定位异常→日志查看详情→链路追踪根因
7. 支撑容量预测、资源计量、SLA报表、月度故障复盘

### 1.3 解决业务痛点
- 监控、日志、链路系统割裂，故障排查需登录多套平台切换工具
- 业务不暴露Metrics，流量突增、延迟上涨无提前预警
- 日志无统一采集，容器崩溃后日志丢失，无法回溯问题
- 链路无透传，微服务调用链混乱，跨服务超时无法定位瓶颈
- 告警泛滥无分级，大量低危告警淹没核心故障，P0事故延迟发现
- 观测数据无租户隔离，研发可查看其他团队敏感业务日志
- 无长期存储，历史指标/日志留存过短，无法做月度容量复盘

## 2. 可观测四层数据采集架构
自上而下分层采集，每层指标独立存储、独立大盘，标签统一互通
```
业务应用层：业务自定义指标、容器stdout日志、OTel链路
集群资源层：Pod/Deployment/Service/PVC、网络、存储、调度指标
平台插件层：Ingress、CSI、Cilium、ArgoCD、Harbor、Cert-manager组件指标
基础设施层：节点CPU/内存/磁盘/网卡、内核、系统服务指标
```
统一全局标签（所有采集数据强制携带）：
`env、team、app、namespace、workload_kind、node_name`

## 3. 四大核心子系统设计
### 3.1 Metrics 指标系统（Prometheus + Thanos）
#### 架构选型
1. 采集侧：Prometheus Operator 管理集群Prometheus实例，按租户分片采集，避免单实例性能瓶颈
2. 远程存储：Thanos全局聚合，分冷热存储
   - 热数据（7天）：本地SSD快速查询，用于实时告警、大盘
   - 冷数据（180天）：对象存储归档，用于容量复盘、合规审计
3. 可视化：Grafana统一看板，预置分层标准大盘

#### 标准化采集规则
1. 基础设施指标：node-exporter全节点部署，采集硬件、内核、磁盘IO、网络带宽
2. K8s集群指标：kube-state-metrics输出所有资源对象状态、配额使用率、副本数
3. 平台组件指标：Cilium、CSI、Ingress Controller、CoreDNS、Metrics Server内置metrics自动发现
4. 业务指标强制规范：
   - 统一端口`9091`暴露/metrics接口
   - 基础指标：request_counter、request_duration_seconds、error_counter
   - 业务自定义指标必须绑定标准标签，禁止无标签裸指标

#### 租户隔离规则
- Prometheus分片按Namespace/团队隔离采集，研发Grafana账号仅授权本团队指标视图
- 集群全局指标（节点、etcd、控制平面）仅开放给SRE运维

### 3.2 Logging 日志系统（Loki + Promtail）
#### 采集链路
容器stdout/stderr → Promtail DaemonSet全节点采集 → Loki多租户存储 → Grafana日志检索
1. 采集规范：业务必须输出JSON结构化日志，字段统一`timestamp、trace_id、level、msg、error_code`
2. 日志分层：
   - 容器业务日志：保留30天
   - 平台组件/集群审计日志：保留180天（合规强制）
   - 宿主机系统日志：保留90天
3. 过滤规则：自动过滤海量DEBUG日志，支持按需开启调试日志存储

#### 安全隔离约束
1. 日志携带Namespace/team标签，Grafana基于RBAC过滤跨团队日志访问
2. 自动脱敏：日志中的密码、token、手机号、身份证自动替换为掩码，防止敏感数据泄露

### 3.3 Tracing 分布式链路（OpenTelemetry + Jaeger）
#### 标准化透传规范
1. 全局注入OpenTelemetry Collector Sidecar，无侵入采集链路，无需业务改造
2. 强制透传TraceID，日志、指标、链路通过TraceID关联，一键跳转溯源
3. 链路存储：生产链路保留7天，测试链路保留3天，采样策略区分环境
   - prod：100%全量采样（核心交易链路）
   - staging：50%采样
   - dev/test：10%采样，降低存储开销
4. 支持调用拓扑图、慢查询统计、跨Namespace微服务调用分析

### 3.4 Alert 告警治理体系
#### 告警分级标准（全局统一，所有告警严格遵循）
| 等级 | 定义 | 通知渠道 | 响应SLA |
|------|------|----------|---------|
| P0 重大故障 | 核心生产业务不可用、集群整体瘫痪、数据丢失风险 | 电话+短信+企业微信 | 5分钟内响应 |
| P1 严重故障 | 单业务服务中断、数据库不可写、大量5xx错误 | 短信+企业微信 | 15分钟内响应 |
| P2 一般故障 | 资源配额临近上限、快照备份失败、少量报错 | 企业微信 | 2小时内处理 |
| P3 预警 | 使用率缓慢上涨、证书即将过期、闲置资源 | 每日巡检报表 | 当日处理 |

#### 告警降噪机制
1. 告警分组：同一应用/同一节点故障合并为一条告警，风暴抑制
2. 告警静默：测试环境夜间22:00-8:00关闭非P0告警
3. 告警自愈：内置自动修复脚本（Pod重启、扩容、清理闲置资源），自愈成功自动关闭告警
4. 告警屏蔽：支持临时屏蔽指定业务告警，留存屏蔽审计记录

#### 告警模板标准化
预置全场景告警规则：
- 基础设施：节点离线、磁盘满、网卡丢包、CPU持续高负载
- 集群资源：Namespace配额80%、PVC使用率90%、Pod重启频繁
- 网络：NetworkPolicy大量拒绝、Ingress 5xx突增、TLS证书过期
- 存储：快照失败、CSI离线、IO延迟过高
- 业务：错误率飙升、接口延迟超标、副本数低于最小副本

## 4. 统一可视化大盘分层
### 4.1 平台运维大盘（SRE专用）
1. 集群总览：节点数量、资源总使用率、Namespace配额占用、告警汇总
2. 控制平面大盘：etcd读写延迟、apiserver请求量、调度失败次数
3. 平台组件大盘：Cilium、CSI、Ingress、GitOps组件运行状态
4. 存储大盘：PVC容量、IO性能、快照备份任务状态

### 4.2 业务自助大盘（研发自助查看）
每个业务自动生成标准化大盘，无需研发自行配置：
1. 服务SLA大盘：QPS、错误率、P95/P99延迟、在线副本数
2. 资源使用大盘：Pod CPU/内存使用率、HPA伸缩记录
3. 存储大盘：PVC容量、读写IO延迟
4. 网络大盘：入站流量、跨Namespace访问拒绝统计
5. 链路慢查询TOP10、错误日志实时面板

## 5. 租户数据隔离机制（联动02-namespace-resource-governance）
1. 采集侧：所有数据强制注入team/env/namespace标签作为分片依据
2. 存储侧：Loki/Thanos开启多租户隔离，通过标签过滤数据
3. 访问侧：Grafana对接OIDC（01-cluster-access-management），基于用户分组自动过滤权限
4. 禁止研发查看其他业务生产日志、链路、核心指标，跨团队查看需审批工单

## 6. 容量规划与计量报表
1. 自动输出月度资源报表：CPU/内存/存储实际占用、Pod运行时长
2. 预测能力：基于历史指标预测未来30天资源水位，提前扩容预警
3. 闲置资源统计：低使用率Namespace、长期0副本应用、闲置PVC，推动资源回收降本
4. 分团队成本账单，对接平台自助门户展示

## 7. 安全与审计联动（15-compliance-audit）
1. 观测平台访问日志留存180天，记录用户查看敏感日志、指标操作
2. 异常访问告警：大量查询其他团队日志、批量导出链路数据
3. 审计报表：每日异常网络访问、Pod崩溃、存储快照失败汇总
4. 脱敏规则落地，防止日志泄露数据库账号、API密钥等敏感信息

## 8. 落地强制禁忌规范
1. 禁止业务自建独立Prometheus、ELK、链路追踪组件，统一接入平台观测底座
2. 禁止业务不暴露标准/metrics接口、非结构化纯文本日志
3. 禁止删除全局统一观测标签，禁止无标签指标/日志
4. 禁止生产链路关闭全量采样，核心业务链路不可降级采样率
5. 禁止关闭日志自动脱敏，日志中明文输出密钥、证书
6. 禁止自定义告警等级，所有告警必须匹配P0~P3分级标准
7. 禁止研发无权限查看跨Namespace业务日志、链路、集群全局指标

## 9. 跨模块协作边界
1. 01-cluster-access-management：Grafana OIDC登录，基于用户分组实现观测数据权限隔离
2. 02-namespace-resource-governance：基于Namespace标签分片采集数据，配额使用率作为核心告警源
3. 04-application-delivery：应用发布自动注入观测标签，发布过程指标联动大盘展示
4. 05-network-security：采集Cilium流量日志、NetworkPolicy拒绝事件，网络异常告警
5. 06-storage-platform：采集CSI、PVC容量与IO指标，存储故障统一告警大盘
6. 11-addon-management：Metrics Server、Prometheus Operator、Loki、OTel Collector属于平台基础插件统一运维
7. 14-platform-engineering：开发者门户嵌入Grafana大盘，自助查看业务监控与日志
8. 15-compliance-audit：观测平台访问日志、脱敏规则、异常检索行为纳入合规审计范围
